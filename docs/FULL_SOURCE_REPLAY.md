# 全量来源有限遍历

`source_coverage_profile="all_actual_training_rows_v1"`显式要求每次有限遍历完整选择所有实际训练来源。当旧课数量大于新讲解时，可由最大的旧课提供有限遍历锚点，讲解和其他旧课仍全部保留。未选择此配置时，原有主来源锚点及采样合同保持原行为。

## 三层覆盖检查

蒸馏编译器从已完成、未截断且未使用独立测试的分词预检取得实际来源数量；按配方计算的有限选择必须逐类等于原始数量。SFT准备再读取全部原始训练文件，拒收未声明来源、只选择子集的权重或数量变化。原生采样器再次检查提供的数据，并把完整覆盖配置写入有限遍历状态及精确续跑合同。

当前真实六来源数据有1114条不同严格讲解，四门旧课训练行数分别为1792、1536、1792、1536，共7770行。实际CPU检查已证明：未选择新配置时，SFT因讲解不是最大来源而拒绝；显式选择后，原生SFT准备通过，有限采样完整选中7770个原始行索引。

名义全局批量32、微批量1、四卡时，每次完整遍历243次优化更新，四次遍历上限972次。原有分布式尾部规则会增加2个填充重复；填充单独记录，不是新讲解、独立棋局或额外不同训练样本。实际更新仍须经过数据、显存和恢复预检，CPU预算不是已训练步数。

## 数据和容量预检

[模板](../configs/search-distillation-sft-full-source-v1.json)记录当前1114＋6656快照的来源数量，并使用[2984条原始联合验证](JOINT_DISTILLATION_VALIDATION.md)。换数据时须从新分词预检重新填写来源权重和回放路径，不能沿用旧数量或静默丢弃行。编译器会将来源数量转换为概率，有限选择数量保持不变。

容量与恢复预检使用32条实际最长训练讲解、12条最长验证讲解以及原回放路径。它显式采用讲解0.8、其余来源合计0.2的有界配比，确保短探测确实处理最长监督序列；所有旧课序列长度仍须不大于该容量探测。预检配置移除正式的全量覆盖及联合验证声明，结果分别记录正式来源覆盖版本和“有界预检不是完整正式训练覆盖”。这防止把几次容量更新谎报成全部数据已训练。

正式SFT继续使用全量配方；完成时从实际有限遍历状态核对覆盖，并核对原生训练保存的完整联合验证ID。原生训练循环与模型架构保持，原先选择0步的失败实验不变。新配置没有取消四卡完整参数、连续四步与两步加两步精确一致、输入隔离或最终独立测试要求。

## 证据范围

16项新增、171项相关CPU检查覆盖编译、原始文件、真实索引、直接采样、填充／续跑，以及受控的容量预检到正式轮次。真实7770行CPU读回与准备通过，缓存和分词另行执行。受控模型不代表实际GPU训练；该本地全旧课回放方案也不等同于论文15万条新讲解规模，棋力和教学质量仍须实测。
