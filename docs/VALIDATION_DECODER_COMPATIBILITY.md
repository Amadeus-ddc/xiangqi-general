# 已有验证参考与评分解析器的兼容范围

评分恢复将“引擎返回合法最佳着、但没有该着的精确分数”从普通 `RuntimeError` 改为其子类 `UnscoredBestMove`，保留原始引擎输出供诊断。该情况仍然拒收，不能用上下界替代精确分数。已有七类辅助数据及搜索保护清单记录的是修改前的解析器身份；直接使用新版重开旧清单会在完整性检查处失败。

`search_protection` 只接受一项明确的历史兼容：旧解析器 SHA256 为 `2bed40736e2d0e4fe05405783a60bb85073ee92876f79aadf6863ea1c53edb19`。其余数据依赖模块必须逐字节相同，语料生产者记录的身份也必须对应这个版本。原生检查器校验当前异常类的完整 AST，将唯一的类型化抛错还原后，整个解析器模块的 AST 必须与固定的旧版 AST 摘要一致。该检查不导入或执行数据产物提供的代码；评分、候选选择、规则、输出字段或其他异常语义的变更均会被拒绝。

兼容协议 v2 的摘要只规范化空的 `type_params` 字段，保留实际的泛型参数和所有其他 AST 内容，并在计算前复制语法树。[Python 3.12 的 AST 文档](https://docs.python.org/3.12/library/ast.html#ast.ClassDef)记录了相对 Python 3.11 新增的类型参数字段；规范化使仓库要求的两个 Python 版本校验同一份普通解析器时得到相同摘要。最小回放保留了未修正版本错误拒收 Python 3.11 形状的失败；对应回归测试同时检查非空类型参数仍被拒绝。本地模拟 AST 形状与 CI 中实际运行 Python 3.11 分别提供证据。

兼容只允许重新核验，不能直接沿用旧保护清单。使用新输出目录执行原生 `xqgeneral.search_protection`，完整重建全部原始验证参考变化、未使用的候选后缀及颜色镜像，逐字节对照既有验证标签，并在新合同中记录两版解析器身份与兼容协议。原始语料、训练检查点和旧保护产物保留。新搜索必须显式选择这份新清单，并再次通过原生 `checked_protection`。

```sh
python -m xqgeneral.search_protection --data /path/to/completed-auxiliary-corpus --output /path/to/fresh-protection
```

`tests/test_search_protection_decoder_upgrade.py` 覆盖真实准备／重开入口、错误生产者身份、其他源码变动，以及评分或异常内容发生变化时的拒收。现有保护测试继续检查验证标签、参考、来源、顺序、完整变化足迹和镜像的完整性。上述检查覆盖 CPU 数据与证据兼容，不证明搜索有效产出率、棋力或讲解质量；独立最终测试不参与重建。
