# 辅助模型和搜索蒸馏模型的搜索试批

`xqgeneral.search_pilot` 仍使用原有搜索、教师汇总和标签收取入口。新增准入检查只读取完成
证据和验证产物，不生成学生回答、不调用引擎或教师，也不启动 SGD。通过准入后，试批
才按原始配置执行真实生成。初始 SFT 的历史合同保留；辅助和搜索蒸馏模型使用各自类型。

## 开始前的条件

- 选中的完整模型必须通过原生训练完成检查。辅助轮次可来自已经声明、实际完成的三卡
  或四卡配方；不能把四卡优化器状态直接称作三卡精确恢复。
- 以该模型完成原讲解验证集的 normal／zero／shuffled 三组回答及完整教师辅助盲评。
  验证行、缓存、引擎资产、原始回答、判断行、全部接受及拒收评分必须保留。
- 辅助模型及其后代必须提供对应辅助语料的[完整保留位置证据](SEARCH_PROTECTION.md)。
  入口沿原生父模型完成证据追溯到初始 SFT，每次只增加实际训练的那一类轮次数。
  不能通过删掉辅助轮次数让后代丢失验证参考范围。多个不同辅助语料暂要求先有完整
  联合证据；当前入口明确拒绝这类情况，不静默只保护最近一份。

验证得分很低、非法回答或教师评分拒收仍保留；这里检查证据完整性，不设置新的质量
通过线。试批不能把未完成验证、只含汇总表或其他模型的成绩当作当前模型的完成证据。

## 配置与运行

继续使用现有试批配置，`evaluation_config` 指向该模型实际完成评测的原配置。辅助及其
后代还须设置 `protection_manifest`，指向 `xqgeneral.search_protection` 的完成清单。这个
字段实际转交矿工；矿工和标签收取分别重建证据，试批核对原生矿工保留的同一保护身份。

```bash
python -m xqgeneral.search_pilot \
  --pipeline ACTUAL_COMPLETED_ROUND \
  --validation ACTUAL_COMPLETED_PAIRED_EVALUATION \
  --producer-session OWNED_EVALUATION_SESSION \
  --config FROZEN_PILOT_CONFIG.json \
  --output FRESH_PILOT_OUTPUT
```

资源分配由运行器控制，当前服务器明确排除物理 GPU2。开始前须取得对应 GPU 租约，
使用独立输出和冻结配置；示例本身不取得资源，也不表示实际模型搜索已经运行。

## 明确复用历史评测源码

若保存的神经评测来自另一份冻结源码，在试批配置中明确声明：

```json
{
  "validation_source_manifest": {
    "path": "PRESERVED_SOURCE_RUN/source-manifest.json",
    "sha256": "EXACT_64_CHARACTER_SHA256"
  }
}
```

入口核验清单、全部 Python 文件和保存产物中的完整源码身份；不会执行其中代码。
检查原生记录／指标回读函数、评分解析器及必要依赖与当前消费者相容，并重读全部三组
原始回答、判断、指标和教师原始评分。历史清单目录保持 `source/xqgeneral/*.py` 结构。
这只是保存产物的兼容回读，不宣称不同推理部署在数值上相同，不重新执行引擎裁判。
没有该声明时必须匹配当前完整源码身份，不能隐式接受另一版本的评测。

## 结果及边界

完成清单区分 `auxiliary_*_search_yield_pilot`、`distilled_*_search_yield_pilot` 与原初始类型，
报告真实选中步数，并沿用已完成的辅助／搜索轮次数。试批的新 SGD 轮次数始终为零；
接受标签数、拒收、原始搜索错误与质量分开记录。

CPU 控制只证明这些原生边界能接受或拒绝对应证据。真实新模型搜索产量、三卡正式
搜索蒸馏、棋力和讲解收益仍须另行运行、读回并评测。独立最终测试不参与训练或选模。
