# 讲解预检的基础模型资产

课程与讲解数据预检检查数据、词元和专家特征；它们不必加载基础语言模型，也不保证在清单中记录完整模型权重。完整参数容量预检此前从课程数据预检的 `inputs` 中寻找权重。实际数据清单没有这些记录，会在 GPU 启动前报 `Pinned base weights are not hash-bound`；旧受控测试额外注入了权重记录，未覆盖实际组合。

需要另行固定模型资产时，在讲解配方中明确声明：

```json
{
  "pinned_base_model_manifest": {
    "path": "/absolute/path/to/pinned-decoder.json",
    "sha256": "<the completed manifest SHA256>"
  }
}
```

该清单采用项目的证据格式：`status` 为 `complete`，`kind` 为 `pinned_local_decoder_assets`，`config` 只包含所选父模型的 `model_path` 与 `model_revision`，`inputs` 为每项本地 decoder 资产的 SHA256 和字节数。资产覆盖配置、词元器、权重及索引引用的全部分片，并使用模型交付模块的同一套本地完整性检查；路径、版本、清单或文件内容不符时，在模型初始化前拒绝。已有数据预检中的模型绑定也须一致。

完整参数预检将清单及全部资产写入自己的合同和证据，并继续执行原来的最长样本、四 GPU、连续 4 步与 2+2 续跑比较。顺序训练控制器在正式 SFT 前后继续检查这些资产，防止预检通过后更换权重。旧式清单已经包含权重时，原入口继续可用。

受控测试覆盖真实的“数据清单不含权重”组合、单文件与分片模型、错误版本／路径／哈希、遗漏或外加资产、历史绑定冲突和正式训练阶段的权重改动。受控张量与进程检查不提供真实 GPU 容量、训练完成、棋力或讲解质量结论。
