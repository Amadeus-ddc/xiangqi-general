# 首轮蒸馏模型的同设置完整对弈

首轮扩充蒸馏模型的384局开发对弈已启动等待。它只在真实轮次完成，并通过课程保持率、三组讲解及正文辅助评审的完整性核验后执行。[部署证据](../evidence/first-scaled-distillation-full-matches-v1.json)记录实际等待进程读回、冻结源码及CPU准备。目前没有该模型的新对弈结果，正式蒸馏更新仍未开始。

## 相同的开发比较

| 项目 | 固定设置 |

两套比较均重新读取完整原始棋局和逐回合证明，确认开局、初始局面、已有着法、执棋颜色、节点预算以及推理／评分源码相同。双方全部384局完成后才比较；非法走法弃负和其他原始错误保留。截断局不计和棋，也不产生分差，64个开局下的场次不宣称为384个独立样本，不换算Elo。这是开发候选比较，最终独立测试继续保留。

## 真实权重与资源门槛

既有`clean_sft_matches`原生接受`full_decoder_search_distillation_sft_round`，直接重新核验完成轮次、实际完整FP32所选权重、训练证明和原生预检。课程与讲解开发评测必须已经评估同一所选检查点；实际完成蒸馏轮次数须为1。实际评测配置仍由前置任务在真实轮次完成后生成，没有构造虚假的完成流水线。

任务在物理GPU 1运行前取得共享启动锁，并确认至少32768MiB空闲。锁只覆盖启动阶段：观察到该次子进程新增的原始模型回合后释放，既有恢复回合不算新加载；子进程完成或失败也释放。四项真实OS子进程检查覆盖正常、恢复、已完成和失败，未知显存占用不终止。

## 检查范围及恢复

原生开局及完整384场调度检查、两个实际CLI帮助入口通过，没有初始化CUDA或加载模型。由于未来评测配置尚不存在，开局检查明确使用已完成的37标签CPU合同控制，只改变评测配置引用；该控制不是未来扩充数据、正式训练或棋力证明。实际执行时仍重新核验真实评测配置与权重。

27项CPU检查覆盖配对条件不一致、残缺场次、共同重复或错误预算、截断与非法弃负，以及原生完成轮次对弈矩阵和真实启动锁。公开113模块及306份源码／测试／配置逐项不变，本地复用既有2087项完整CPU检查，没有重复相同套件；本地构建与发布检查通过，实际开局调度与联合候选逐字节相同，受控终局另经完整384场配对检查；这不等于真实棋局。远端继续执行既有CI。

固定计划、运行源码、输入哈希和实际进程身份保存在服务器运行目录，长任务位于tmux。失败时保留原始错误和未完成棋局，仅在相同轮次、配置、源码及合同下续读原生进度；不得为了恢复而覆写失败记录或更换候选。

公开入口已经支持真实完成的轮次，可在全部实际产物就绪后使用：

```bash

```
