# 复用已核验的输入哈希

课程按固定间隔保存检查点、执行原始回答验证，再恢复训练。原入口在每次启动时完整读取全部训练输入；缓存加载和产物清单也会再次哈希特征文件。数TB特征因此会反复占用读取时间。

`verified_inputs.py` 提供显式的核验会话。它从完整生产者的证明中读取 SHA256、字节数和文件签名，在文件身份保持一致时复用已有哈希。模型、损失、优化器、随机种子、有限轮次采样和课程选模规则保持原实现。普通 `digest` 调用仍执行完整哈希。

## 生产者与消费者

生产者调用 `write_verified_input_receipt`。每个绝对、规范化路径需要以下三项：

```python
bindings[path] = {
    'sha256': successfully_computed_sha256,
    'bytes': verified_size,
    'signature': [device, inode, size, mtime_ns, ctime_ns],
}
```

签名必须来自实际完整字节核验过程。把当前签名附到一份未经核验的预期哈希上，不能建立有效的生产者证据。正式大输入证明应在来源、缓存和基座完整读回成功后发布。

生产者在发布前后检查绑定；近期写入的文件需要等待两秒的稳定窗口，再完整重算字节哈希。这处理了文件系统时间戳更新粒度小于其表示精度时，快速同大小覆写可能保留相同签名的问题。消费者拒收仍处于该窗口、时间位于未来或身份已变化的输入。

课程命令可以显式接收一份已发布证明：

```bash
XQGENERAL_VERIFIED_INPUT_RECEIPT=/path/to/verified-inputs.json \
  python -m xqgeneral.validation_curriculum --config /path/to/foundation.config.json
```

环境变量只在 `training.main`、`evaluate_qa.main` 和 `validation_curriculum.main` 打开的会话中生效。命令启动、每次哈希复用、证明记录以及正常退出时都会核对文件签名。会话在异常时恢复先前状态。文件身份变化会报错，需要完成新的字节核验并使用相应的新运行合同。

未纳入生产者证明的新检查点和输出仍完整哈希；足够稳定且身份一致的文件可以在本进程内复用刚刚计算的结果。近期输出继续实际读取字节，支持快速连续保存检查点。

## 证据与续训

训练的 `execution.json` 和会话中的产物清单记录 `input_digest_verification`，包括证明SHA256、复用文件及调用数、避免的字节读取量和实际完整哈希调用数。复用计数与本进程重新读取字节的计数分别记录。

输入哈希值及其路径键保持原合同。新执行源码的身份仍进入检查点、课程合同及原始验证清单；原有源码一致性和DDP世界大小检查继续约束断点恢复。首次使用新执行版本需要全新实验，之后在同一版本内恢复。

入口回归测试直接调用首次训练与续训入口，观察真实输入文件的二进制打开次数，并核对下游收到的哈希映射。边界检查覆盖同大小覆写、恢复原修改时间、替换文件、会话内变化、异常清理、近期文件及默认完整哈希行为。正式数值资格还需要使用实际预训练模型、原专家特征和四卡训练，比较全部参数、优化器、随机状态、数据状态与训练轨迹。

输入核验测试和数值资格检查都不代表完成了正式四门课，也不证明学生棋力或讲解质量。
