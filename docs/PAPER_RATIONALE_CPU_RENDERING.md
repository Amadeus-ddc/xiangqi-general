# 新监督语料：在原生工作进程完成文字渲染

2026-10-31完成实际CPU对照及1799项完整检查。相同2048道真实训练题、两组均32个工作进程，在全新父进程与工作进程中，旧计算位置耗时451.69秒，工作进程内渲染耗时35.24秒；全部输出记录逐字段一致，整体SHA相同。这是固定样本的约12.82倍加速，不是完整语料的速度承诺，也不是模型正确率提升。见[结构化证据](../evidence/paper-rationale-worker-rendering-v1.json)。

## 已测量的瓶颈

旧并行路径先在原生工作进程验证完整历史、计算答案，再把记录送回主进程。主进程调用`with_rationale_profile`生成新增逐着叙述与应将机制时，会重复计算部分棋盘事实，且无法使用工作进程中的规则缓存。

独立CPU进程只测同一2048题的文字渲染，空缓存首次耗时442.99秒；相同进程按同顺序再次执行耗时44.93秒。两轮均逐字段等于已准入的新标签，输出SHA一致。这说明缓存状态会显著影响耗时。此前先8后32进程的459.16／57.19秒观察同时受缓存和执行顺序影响，不能将其约8倍差异全部归因于工作进程数。

## 实现与输出约束

声明了`rationale_profile`且启用多个问句工作进程时，原生批次在验证完整历史和完成原答案后，立即完成该记录的监督文字，再返回主进程。生产者和独立原生读回都使用此路径，主进程不再重复渲染。

自适应问题选择及频率更新继续按原顺序处理原问题，然后才生成新身份和答案。种子、问题、局面、来源历史、最终标签与新身份算法没有改变；不增加配置开关。单进程与未声明新监督的路径继续兼容既有配置。

完整CPU检查覆盖三种监督配置的单／多进程数据字节一致、原生读回、应将题实际覆盖、未知配置提前拒绝及伪造历史拒绝。计算位置的回归检查在旧代码上实际失败，修复后生产与读回均不再调用父进程渲染。

## 相同真实样本的隔离对照

两种方式各自启动全新父进程及32个spawn工作进程，初始Python规则缓存为空，均执行完整原生历史验证和原答案生成。使用既有基准的相同2048条训练索引、每批4个原生组，最终每条记录均与已准入标签比较：

| 计算位置 | 完整样本流程秒数 | 输出SHA前缀 |
| --- | ---: | --- |
| 原生工作进程后，由主进程渲染文字 | 451.69 | `071eea723bb2` |
| 在原生工作进程内完成文字 | 35.24 | `071eea723bb2` |

候选方式的父进程原生规则缓存始终为空，证实没有把同一计算再搬回父进程。两份111模块源码只在课程数据渲染相关的两个模块不同；完整源文件与样本、结果哈希保留。

该对照包含原生工作内核、进程池生命周期、监督渲染及记录比较，不包含完整来源采样、SQLite和全语料I/O。执行顺序为原方式后候选方式，机器负载与操作系统页缓存未控制；不据此推算全语料完成时间。检查共享生产的原生规则实现，不是独立第二规则引擎。

## 训练与运行边界

实际数据作业须使用新输出目录和冻结源码，沿用真实哈希与未变文件身份的输入凭据，保留旧部分产物。切换只允许终止已绑定的自有CPU生产者及等待预检；GPU模型对照、原QA租约和训练权重不属于这项切换。

完整新语料仍须全部原生来源读回、10833161条新旧配对，以及训练／验证的索引、特征、历史、切分与严格词元预检后才能训练。以上软件和样本性能证据不等于全量数据准入。
