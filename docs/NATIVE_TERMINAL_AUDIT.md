# 候选分支的杀棋步数复核

`xqgeneral.terminal_audit` 使用原生中国象棋规则和完整历史，搜索候选落子后的将杀或困毙证明。它用于复核训练标签里的候选分支评分：胜率过滤会把不同步数的必胜估计都映射到相同胜率，因此通过胜率过滤仍可能带有错误的杀棋步数。

结果分为三类：

- `positive_distance_contradiction`：找到并重新复演了更短的必胜上界，与该候选声称的步数矛盾。
- `no_witness_within_bound`：给定步数内没有找到证明，原评分仍未被认证正确。
- `resource_exhausted`：达到时间或状态检查预算，结论保持不确定。

## 单条训练候选的入口

输入 JSON 包含 `record` 和 `branch`。`record` 必须显式标为 `train`，提供完整 `initial_fen`、`moves` 和当前 `fen`。`branch.evaluation` 是该固定候选的根行棋方视角估计，类型为 `mate`，绝对值大于一。

例如，以下手工局面中的黑方候选声称负三步杀；复演后红方实际下一手即可将杀：

```json
{
  "record": {
    "split": "train",
    "initial_fen": "9/9/1N2k4/7R1/4R1b2/9/9/9/5K3/9 b - - 0 1",
    "moves": [],
    "fen": "9/9/1N2k4/7R1/4R1b2/9/9/9/5K3/9 b - - 0 1"
  },
  "branch": {
    "move": "e7d7",
    "evaluation": {"type": "mate", "value": -3, "perspective": "side_to_move"}
  }
}
```

保存为 `case.json` 后运行：

```bash
python -m xqgeneral.terminal_audit \
  --input case.json --output audit-attempt-1 \
  --max-winner-moves 3 --max-state-checks 100000 --seconds 45
```

输出目录必须是新目录。`audit.json` 保存完整证明树和原始候选绑定，`manifest.json` 保存输入、源码、输出哈希及执行边界。入口不修改标签、评分或正文，不调用语言模型或引擎，也不自动把数据收进训练集。较长批处理应在 tmux 中运行并保留每条输入和结果。

## 证明范围

步数按最终获胜方的落子次数计算。审计候选时，若固定的第一步属于获胜方，它计入一次；若它属于败方，则不计入。搜索上限默认三次获胜方落子，可设为零到八次的通用证明预算；候选审计上限必须为正，并始终小于被核查的宣称步数。

证明树在获胜方节点选择一着，在对手节点覆盖全部原生合法应手。安静着造成的困毙同样纳入搜索；每步之前检查完整历史终局。仅凭一条配合变化提前结束，无法构成覆盖全部应手的证明。AXF 规则产生的其他终局会停止继续走棋，但不会被当作将杀或困毙证据。

一着终局探测先检查是否还有合法应着，零应着时才执行完整历史裁定以确认赢家。其余节点在实际展开前执行完整裁定，遇到 AXF 终局立即停止。局面及裁定缓存均绑定完整走子历史，保留安静着困毙和规则终局的区别。

`verify_terminal_certificate` 独立遍历证明树，重新枚举对手应手并核对每个终局叶子、赢家、局面、历史和距离。它与搜索使用同一套原生规则，因此这不是独立规则实现。状态检查次数是搜索及缓存操作次数，不等于不同局面的数量；时间预算约束搜索过程，输入验证和证明复演另计。

这里核查的是固定候选分支的评分。全局根评分描述原局面的最佳行棋，可能与最终推荐候选的距离不同，不能把它直接代入某个固定候选来断言矛盾。正向证明给出上界，不保证最短步数；未找到反例也不能认证原有杀棋距离、战略讲解或模型棋力。

用于实际整条标签排除时，还需绑定最终原生卡的 ID、原查询、回答和正文哈希，并完成原有保留集隔离、去重和讲解复核。运行中的冻结生产配方与旧 `+/-1` 检查合同保持各自原始身份；这个离线入口提供额外证据。
