# 课程分割核验的CPU并行入口

2026-10-31。课程生成和完整来源复核增加 `--split-workers`，把既有的多进程分割核验接入原生入口。新选项只控制分割核验的CPU进程数；问题生成、金标、输入字节核验和完整来源重建继续执行。[结构化证据](../evidence/paper-split-workers-v1.json)记录实际测量及回归结果。

## 实际测量

同一份已验证的20000条训练样本包含19935个不同的分割核验上下文。使用冻结原生实现，按1、8、1、8个进程的顺序，分别重新加载数据、执行核验：

| 进程数 | 第一次 | 第二次 | 中位数 |
| --- | ---: | ---: | ---: |
| 1 | 297.86秒 | 297.52秒 | 297.69秒 |
| 8 | 38.91秒 | 40.64秒 | 39.77秒 |

四次返回的完整分割证明一致；中位耗时之比约7.48。计时只覆盖核验函数，文件加载另计。这是该训练样本上的CPU结果，不能推算整库提速比例、GPU训练速度或模型准确率。样本中的棋局ID是来源声明，不认证独立人类实战。

## 使用与记录

生成新课程时，在原生成命令后增加 `--split-workers 8`；非默认值写入生产清单的 `config.split_workers`。默认仍为1，省略字段的历史清单按1处理。

复核已有完整课程时，可以显式指定本次CPU核验进程数：

```bash
python -m xqgeneral.paper_curriculum \
  --readback PATH_TO_COMPLETE_CORPUS \
  --output NEW_READBACK_DIRECTORY \
  --split-workers 8
```

省略该选项时，复核沿用生产清单中的值。本次显式覆盖值写入新的复核清单，不修改生产清单或已有课程文件。显式传入的非法进程数在读取输入或创建输出前拒收；生产清单中的非法值也不能被覆盖掩盖。输出仍必须使用新目录。跨源码版本的复核仍受下游源码身份守卫约束，进程数覆盖不绕过该检查。

新增接口检查实际执行原生单／多进程核验，核对300条受控课程记录逐字节一致、保存值与覆盖值传递、历史清单兼容、无效参数拒收和CLI接入。54项相关检查与1810项完整CPU回归通过；完整回归绑定293份源码、测试、配置与构建文件的实际SHA，采用项目既有的OMP／MKL／OpenBLAS各1线程设置。结果见结构化证据。

现役课程训练、语料生产与排队推理仍使用各自冻结源码，没有热切换到新入口。完整新语料的来源配对、词元与特征预检、学生收益仍需各自完成；这项改动不证明第四课、讲解或最终模型已经验收。
