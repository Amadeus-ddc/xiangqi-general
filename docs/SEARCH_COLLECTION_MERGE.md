# 多批真实搜索标签的合并

并行搜索采用互不重叠的起始根区间，但递归到达的完整历史仍可能重复。
训练量按去重后的完整历史统计，同时单列原始接受记录、重复记录、实际尝试与接受的起始根数量。

```bash
python -m xqgeneral.merge_search \
  --collections runs/search-a/labels runs/search-b/labels \
  --checkpoint runs/selected-student/adapter.pt \
  --output data/merged-search-round-1
```

所有输入须是原始、完成的 `search_consolidated_dataset` 叶子目录；不接受嵌套合并目录。
每批须来自同一实际所选学生权重、同一原始棋谱池、相同保留集和固定的完整 BF16 教师。
单批可以少于32条，合并后至少须有32个不同的完整历史。
对于包含大规模固定缓存的生产记录，沿用项目的已验证输入回执；命令入口会开启环境所指定的校验会话。

合并会重新打开每批的输入与输出绑定、搜索完成清单、原始根尝试、查询、完整教师推理清单、部署身份、原始回答及权重清单。
原始尝试必须完整对应所选棋谱区间，所有教师回答须覆盖对应查询。
原生历史、事实、显式正文走法、完整变化和严格小于0.075的原始选中分支评分误差过滤均重新检查；拒收记录也须能从原始查询与回答重建。
搜索接受策略须保留原始完成证据：支持原有严格改进策略或论文递归策略，所有合并叶子的策略与最短有效变化要求必须一致。
原始选中分支评分误差仍须严格小于0.075；不重新调用学生、教师或引擎。

按 `--collections` 顺序、再按原文件行序，保留一个完整历史首次出现的记录。
保留行逐字节写入，包括原来的中文转义、空白和换行；不合并或改写不同回答。
`provenance.jsonl` 记录所有保留与丢弃行的源目录、行号、行哈希、保留项索引，以及正文、首着和变化是否不同。
同一个训练ID对应不同历史会拒收；重复目录、路径别名、生产证据不一致也会拒收。

验证和独立测试文件逐字节复制，独立测试只参与隔离及保留核验。
合并后的实际答案变化会再次用于棋局、根局面与未来局面的跨分割检查。
产物清单采用独立的 `merged_search_consolidated_dataset` 类型，保留全部原始生产绑定。
蒸馏预检重新打开该清单时会从原始叶子重建合并结果，核对原行、重复来源和保留集，再进行特征与词元检查。

合并通过只表示数据生产链、原生合同、去重和隔离通过检查。
战略正文的全部语义、教学质量、正式蒸馏更新与棋力收益仍须另外验证。
失败和完成的输出目录均保留；重跑使用新目录。
