# 讲解与蒸馏后的四课验证

`curriculum_replay` 在实际完成的初始讲解模型或蒸馏轮次上复查四课验证集。它补充讲解、正文评审和开发对弈，用于观察课程能力的保留情况；最终独立测试继续按[独立协议](FINAL_INDEPENDENT_EVALUATION.md)在选模结束后执行。

[默认配置](../configs/curriculum-replay-validation-v1.json)覆盖26类题型，每类100题，共2600题。正常、清零、错配专家特征各运行一次，三组使用相同的题目、顺序、问法及生成预算。每条题目只采用一种固定问法，三种问法按题型内顺序分配。默认种子20261046与本次正式课程验证一致；若课程配置不同，应使用对应完成记录中的种子和题目预算。

入口核对实际完成的全解码器模型、选中权重、训练配方和数据预检，并沿已完成的蒸馏来源找到初始讲解及四课完成记录。问答数据必须是该课程实际使用的验证文件；专家特征来自该模型的实际训练配置。未完成模型、测试分割、缺失题型、单条错配批次及变化的输入均拒收。

## 结果

- 保留三组全部原始回答，重新评分并核对每道题的身份、问法、金标和已存成绩。
- 分别报告四课的答对题数、正确率、最弱题型、格式错误、各题型成绩及不同棋局ID数量。
- 报告正常特征相对清零、错配的准确率差异，按四课分别列出。
- 读回原第四课所选模型的原始验证。只有题目、顺序、问法和金标全部一致时，才计算逐课错转对、对转错和原课程分数；不一致时明确记录无法进行同题比较。

不同题型和同一棋局的多道问题属于相关观测，题数不代表独立棋局数。此处不应用“总分99%／最弱95%”等自动合格线。课程成绩、讲解质量和对弈表现需分别评估。

## 执行与恢复

先完成模型训练，再从包含实际模型和数据的项目根目录运行。`--model-config` 使用该模型对应的讲解开发验证配置：初始模型绑定其实际SFT配方和预检；蒸馏模型绑定本轮实际编译配方、预检及扩展缓存。示例中的路径应替换为已完成运行的真实路径。

```bash
.venv/bin/python scripts/freeze_run.py --output runs/initial-sft-course-validation/source-run -- \
  .venv/bin/python -m xqgeneral.curriculum_replay \
  --pipeline runs/initial-sft/pipeline \
  --model-config runs/initial-sft/inputs/evaluation.json \
  --config configs/curriculum-replay-validation-v1.json \
  --output runs/initial-sft-course-validation/results
```

每个蒸馏轮次使用新的配置副本和输出目录，并把`--pipeline`指向该轮`distillation_training`的完成目录。可通过`XQGENERAL_VERIFIED_INPUT_RECEIPT`复用[已核验输入凭据](VERIFIED_INPUT_DIGESTS.md)；变化的文件仍须重新核验。

长任务使用tmux并固定源码。`--resume`只接受相同的模型、源码、输入和配置；已完成的三组结果重新读回、评分，不再次生成。缺少完成清单的原始评测目录保留，另用新的输出目录重做该实验。完整报告的输入绑定、输出绑定及聚合值也在恢复时重新核对。

## 当前证据范围

初始讲解和蒸馏轮次的受控CPU集成检查覆盖三组生成、错误保留、来源绑定和恢复拒收；这类控制使用构造权重及固定回答，不衡量真实模型能力。真实验证数据的2600道题及受控字符串评分，已与现役89模块冻结源码逐字节比较。见[软件与输入证据](../evidence/post-sft-course-validation-v1.json)。

第四课仍在训练，实际讲解后／蒸馏后的四课复查、棋力与教学收益、最终独立验收及训练模型交付仍待完成。
