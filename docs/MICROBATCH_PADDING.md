# 可选的微批次填充裁剪

训练原先把每张卡的一批题补到同一长度，再拆成微批次。长题因此会让其他微批次也计算许多被忽略的填充列。新的 `microbatch_padding` 配置允许每个微批次仅保留其中最长题需要的列。默认值为 `rank`，保留原行为；新实验可显式设置：

```json
{"microbatch_padding": "micro"}
```

该选项不改采样、题目顺序、有效批量、专家特征、损失权重或优化器。只裁去注意力掩码为零且标签为 `-100` 的右侧列；按注意力判断长度，即使 EOS 与填充词元编号相同，也保留有监督的 EOS。左填充、掩码空洞、非二值掩码、空行、被裁区域中的监督标签及额外张量输入会报错。带独立 `position_ids` 或打包序列的输入不在此接口范围内。

课程与 SFT 配方编译器保留并校验该选项。讲解容量检查从同一完整配方生成探针配置，绑定配方哈希；正式讲解与蒸馏还比较实际配置。续跑会把缺省值归一化为 `rank`，并拒绝在 `rank` 与 `micro` 之间切换。启用时使用新输出目录及匹配源码，不能把它加入正在恢复的旧实验。

## 实际训练题抽样

CPU 诊断从现有第二课训练索引和旧课子集规则重建混合池，选取 **2,048 条互异训练行**，组成八个假设的全局 256 批次，按四卡、微批量 4 比较。样本含 1,831 条第二课题和 217 条第一课题，实际长度为 94–292 词元。它没有重放实际完整 epoch 顺序或优化器批次，也没有读取验证、独立测试题或模型权重。

| 统计 | 词元位置数 |
| --- | ---: |
| 未填充的有效输入 | 284,704 |
| 按每卡整批填充 | 484,352 |
| 按微批次裁剪后 | 348,044 |

在该样本上，含填充的词元位置数减少 **28.14%**。逐全局批次取最大卡工作量再求和的词元位置指标从 136,320 降至 91,104，减少 **33.17%**。两者都是位置计数，不能换算成已测 GPU 加速、FLOPs、峰值显存或质量收益。

随后在**同一批** 2,048 条题的真实分词张量上执行候选实现，逐微批次核对保留的输入、掩码、标签、监督目标数和原张量未变；结果与上述位置计数一致。这不是额外 2,048 条独立样本，也没有比较这些真实题上的模型输出或梯度。全量输入哈希沿用已完成的不可变凭据并复核文件身份，本次新哈希约 841 MB 索引文件；没有重新读取约 88 GB 的已验证输入。

## 模型与续跑检查

[CPU 回归](../tests/test_microbatch_padding.py)使用从配置随机初始化的微型 Qwen3、实际 DenseBridge 和非零门控，不下载预训练权重。冻结／完整解码器、词元／逐样本损失归一化及三种微批量均与独立双精度全批参考比较有效位置 logits、损失和全部可训练梯度；同一裁剪配置的连续四步与两步后恢复到四步逐位比较模型和 AdamW 状态。另覆盖默认行为、配置传播、EOS、错误输入及拒绝跨配置续跑。

```bash
CUDA_VISIBLE_DEVICES= python -m pytest -q tests/test_microbatch_padding.py tests/test_training_contracts.py tests/test_training_memory.py tests/test_sft_launch.py
```

微型模型检查依赖可选 `train` 依赖中的 Transformers；未安装时这些模型用例明确跳过，其余张量与配置用例仍执行。完整 4B 模型、BF16 GPU 数值及真实吞吐尚未对照验证。当前正式四课和已排队讲解消费者均保留原冻结源码与配置，未启用此选项。现有课程控制器没有逐段 GPU 空闲准入，不能把一次 QA 间隙视为可用的额外 GPU 作业窗口。
