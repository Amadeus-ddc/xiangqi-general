# 预检中的逐题规则验证与词元检查

全量预检原先在父进程读取每条记录时调用`validate_task`。论文任务的未来局面验证会完整复演其历史；实际栈采样显示父进程在执行这些原生检查，64个词元工作进程大多空闲。未来题开始后，词元计数在约527万条附近放缓。原实际300题CLI的父进程探针复现了这一执行位置。

改动将相同`validate_task`调用放在既有词元工作进程内，在编码之前执行。父进程仍按原顺序检查记录身份与缓存键，累计统计、保存唯一历史和按固定种子抽取答案样本。三个划分的所有记录均进入工作进程；独立测试只验证查询，不编码其答案。训练与验证词元预算、验证集的两种替代问法保持不变。完成时另核对工作进程验证数量覆盖全部记录；任一无效查询或缺失验证都会阻止完成证明。

原规则函数和课程配方不变。唯一历史的原生复演、原生答案样本、完整当前／未来隔离、旧前缀检查及缓存变动检查仍执行。并行执行改变验证的进程与失败发现顺序，不改变已接受数据的验证结果。失败产物保留，不能被描述为完成证明。

三个新检查先失败、修复后通过：实际无效未来走法在编码前拒收；独立测试查询也要验证、其答案不能编码；全部记录验证覆盖与训练／验证／替代问法预算正确。相关60项、全套1517项CPU检查、构建与发布检查通过，243份源码／测试／配置在检查前后不变，其中仅执行模块和测试文件较上一版改变。

真实四进程300题完整CLI的全部原验证字段一致；词元证明与原生答案样本逐字节相同。300条查询全部由工作进程验证，200条训练／验证题编码、12个唯一历史原生复演，原父进程探针不再失败。这是局部入口控制，不能替代10833161题全量验收。

从实际未来训练流选择128个不同历史，以相同原规则验证作对照：串行29.0558秒，四进程预热后8.0779秒，局部约3.60倍；启动与预热另为2.6060秒。较早的16题重复样本未显示加速，其结果保留；独立历史对照避免由重复样本缓存掩盖主要耗时。结果不证明生产全库提速倍数。
