# 讲解训练的多源旧课回放预检

2026-11-05（UTC+8），修复了讲解训练预检中的两个多源数据校验问题。此前训练索引可以包含讲解与旧课文件，预检复核却只重新打开讲解训练文件，导致合法的多源索引被拒绝；已经完成的预检清单又未绑定额外回放的原始训练和验证文件，文件改变后可能错误复用完成结果。

现在复核会打开主数据与全部 `replay_data_paths` 的训练文件，重新检查实际有限轮次状态，并在预检结果中保留该状态。完成清单同时绑定各回放目录的 `train.jsonl` 和 `validation.jsonl`；这些文件改变后，复用必须失败。单一主数据源的行为保持。

## 软件与实际四卡组件验证

新增8项回归使用真实多文件索引与实际有限轮次状态，覆盖零个、一个、两个回放目录，改变训练或验证文件后拒绝复用，原文件保持时无需新worker，以及两边相同但实际错误的轮次状态。GPU产物在这些CPU回归中为受控夹具，不能代替原生训练。

另行执行了真实四GPU小型Qwen组件对照，使用12,580个参数、55个训练张量、合成数据与随机特征。词元平均和逐样本平均两种损失均分别运行连续4步及2+2步恢复，解码器25个、桥28个、棋盘2个张量均更新；模型、Adam、随机状态和实际数据轮次完全一致，参数最大绝对差为0。每种配置的主源19行、回放源12行，实际选择19+6行；两轮共消费50个非填充行呈现和6个分布式填充行。两种配置的四个GPU worker及完成步骤均已实际读回，检查点来源和输入哈希与预检来源相符。

92项相关检查、1,955项完整CPU检查、构建与发布检查通过。原生运行前后的112份模块、303份源码／测试／配置保持匹配，完成后又独立读回。最初原生夹具遗漏棋盘参数，被原有严格检查拒绝；修正夹具后通过，没有降低参数更新要求。另一次CPU夹具检查因反向传播放在棋盘上下文外而失败，失败记录同样保留。

## 已准备的实际回放数据

从原已完成划分的课程训练文件分层抽取26种课程／题型，每种256行，共6,656行；原2,600行验证集保持，未读取或复制独立测试行。抽样过程实际流读并重新哈希原10,804,561行、87,552,607,803字节训练文件，保留原行字节；全部抽取训练行和验证行已重新进行原生完整历史／未来和答案检查。准备产物又另行重新哈希并核对逐行词元清单。

实际最大长度为训练320、验证323个词元，均小于现有讲解预检的649／625长度；没有截断监督答案。训练监督词元共259,109，验证103,719。样本特征键在既有特征目录中，复用了原不可变输入凭据；本次没有重新计算或独立复核全部特征张量值。

这批数据尚未纳入新一轮正式训练。小模型原生对照证明多源索引、恢复与校验路径可执行；它不证明完整4,694,274,592参数学生的混合训练容量、旧课保持或讲解质量改善。正式蒸馏编译器的讲解专用约束仍需另行处理，回放比例与损失归一方式也尚未由实际效果选定。当前1792步学生、正在执行的完整384局与搜索容量检查未修改，最终独立验收仍未完成。
