# 原始引擎日志的走法和数值监督

`xqgeneral.oracle_policy_data` 将已经完成的原生搜索日志重放为训练专用数据。目标是补充直接选招和变化评分监督；完整教师讲解与四门旧课仍须在新的训练配方中明确保留。

| 题目阶段 | 答案 | 独立准入条件 |
| --- | --- | --- |
| `move_quality` | 单个最佳 UCCI 着法 | 合法的原始最佳着法；同一历史不能有最佳着法冲突 |
| `engine_numeric` | `move`、`pv`、`candidates`、`evaluation` 四字段 JSON | 三个不同候选，或全部不足三个的合法候选；最佳变化满六个半步或按完整可用历史原生终局；同一历史不能有最佳着法或精确评分冲突 |

两个问题共享历史时只计一个独立历史。变化不足六步的记录仍可保留可靠的单走法题；仅评分不同而最佳走法相同的重复记录也可保留走法题。候选按实际原始日志取值，上下界不替代精确评分，评分方向为当前行棋方。重复历史按输入来源顺序保留首个通过原生解析的非限定搜索，后续记录不得悄悄补足第一份的变化。

## 来源和隔离

来源必须是完成的 `search_distillation_mining` 清单，绑定原始成功查询日志、明确的引擎及 NNUE 文件、相同解析器和原生规则实现。预算至少十万请求节点，限定着法查询只写入拒收账本。入口核验原始记录的完整可用历史、原生原文重解析、声明的原棋谱范围及其合法后续身份；不将来源棋谱的实际走法当成最佳招标签，也不补造残局 FEN 之前的历史。

复用现有棋谱／课程／讲解的共同保留位置权威集合，检查训练根、所有保存候选变化和颜色镜像。`validation.jsonl` 与 `test.jsonl` 都为空；该入口不创建新验证集、不访问保留集模型答案，也不选择检查点。

## 执行和完成后复读

以下路径是示例，替换为实际已完成来源；保持来源的原项目工作目录以解析旧清单中的相对路径。所有显式资产和来源须先存在，命令不下载或调用模型。

```bash
python -m xqgeneral.oracle_policy_data \
  --mining runs/search-a/mining runs/search-b/mining \
  --authority data/unused-recorded-inputs \
  --data data/courses --heldout-data data/explanations \
  --executable vendor/pikafish/src/pikafish \
  --weights vendor/pikafish/src/pikafish.nnue \
  --seed 20261013 --minimum-nodes 100000 \
  --workers 8 --chunk-rows 1000 --output data/oracle-policy-views
```

长任务放在 tmux，并冻结执行源码。输出保留训练行、原始查询拒收、分阶段历史拒收、重复查询、计数、来源合同和完成清单。每条训练行保留原日志行号、字节位置、原始行哈希、选中棋谱根和搜索后续深度。

对完成目录使用相同命令追加 `--resume` 会重新解析全部输入并重建所有输出摘要，不改写原目录。可以改变 CPU 工作者数量及分块大小；逻辑来源、预算、种子或代码合同改变则拒绝。部分完成目录保留，用新的输出名称重新执行；不覆盖失败产物。

## 验证范围与后续训练

29 项定向 CPU 检查已通过，覆盖两种题型各自准入、冲突、原始日志与历史损坏、伪造棋谱归属、保留变化及镜像、串并行一致和完成后完整复读。单元样例使用受控原始引擎文本和资产身份，不执行真实引擎或模型；真实整库实验另存运行证据。

原型已实际筛出 144932 个数值历史，并完成相应专家特征缓存。这是此前独立原型结果；新公共入口的全量等价性及额外走法题数量仍须实际重放后核验。

原生 SFT 的显式阶段／混合接口可接收这两类题，受控有限遍历检查已通过。现有五阶段搜索蒸馏编译器只接收完整讲解及四门旧课；该入口没有绕过它，也没有把数值题改名为完整讲解。新的混合、词元缓存、特征覆盖和优化预算须单独冻结及预检，不能修改旧检查点配置来冒充训练过的 `move_quality`。

当前没有该数据的新学生更新、合格蒸馏轮次、棋力或教学收益证明。原始数据与模型资产保持各自来源和授权边界，源码许可证不自动授权重分发棋谱、引擎或权重。
