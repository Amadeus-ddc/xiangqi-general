# 扩充数据后的首轮开发蒸馏接续

[等待与接续入口](../scripts/queued_distillation.py)在真实生产任务完成后调用既有`distillation_training.run_round`，由后者建立实际数据索引，先完成完整模型四卡原生预检，再允许正式参数更新。等待程序不代替标签、词元、容量或模型质量检查。

## 本次候选的身份与规模

当前扩充搜索使用原初始讲解训练选中的1792步模型，因此首轮开发蒸馏继续使用这个父模型。正在训练的新联合讲解模型是另一个候选，分别保存和评测；不能用它替换搜索父模型。

本机首轮开发下限设为去重后至少512条合格讲解，并要求三批各512起始局面的实际生产、完整重建合并、特征扩展及词元预检完成。这是开发规模下限，不是原论文约15万条首轮标签规模。既有37条配置控制和70条小型合并不能绕过扩充要求。起始局面、教师接受记录和去重后的完整历史分别计数。

采用[显式FSDP2配方](DISTILLATION_FSDP2_FINITE_BUDGET.md)，讲解80%／每门旧课5%、逐样本损失，完整FP32可训练参数、全局批量32及微批量1。最多四轮实际舍入混合数据，三万步为硬上限；旧课不计入新蒸馏标签规模。四轮是首轮开发预算，后续是否扩充数据或调整训练量，依据开发结果决定。

## 开训条件

- 当前执行脚本、全部训练源码、固定小文件与冻结计划SHA完全匹配，完整CPU检查证明包含同一份接续脚本。
- 数据准备和新联合模型的课程／讲解开发评测任务正常完成，退出凭据绑定实际完成证明。等待期间核对PID、启动时间和命令SHA；状态文件本身不能证明进程存活。
- 实际扩充集合达到本机下限，父模型、特征与完整词元证明一致，原384条讲解验证和512条独立测试保持。独立测试不产生学生预测、不训练或选模。
- 配方在CPU按实际训练文件编译后，更新预算和五项显存设置进入最终配置。
- 取得项目共用教师／训练锁，四张卡各有至少35840MiB空闲；不终止来源不明的其他任务。取得资源后重新核对所有完成凭据和准备输入。
- 既有`run_round`重新校验完整原生标签、分割隔离、父权重、特征与词元绑定，并对最长实际监督执行全部参数初始化、容量及连续4步对2+2步精确恢复检查。任何一项失败都不能进入正式SGD。

等待完整联合模型开发评测是本机资源与评测优先级安排，不会把它的权重或评测答案用作旧模型蒸馏监督。后续强度与教学改进必须从所选新权重的实际开发评测得出；训练正常退出不是能力提升证明。

## 冻结执行与恢复

服务器计划保存在独立运行目录，不提交机器路径、模型、数据或日志。计划明确列出原始生产任务、执行源码及检查证明、父模型、词元与特征清单、配方、共享锁、输入凭据和独立轮次输出目录。

在计划指定的源码环境和四卡可见设置下，用tmux运行冻结脚本，传入冻结计划的实际SHA：

```bash
python FROZEN_ENTRY.py --plan RUN/plan.json --plan-sha256 SHA256_OF_FROZEN_PLAN --output RUN/controller
```

查看`controller/state.json`、`owner.json`及`exit.json`。只有退出0且完成证明可重新读回时，才算该接续完成；排队不算训练开始。等待或容量不足不会自动重启模型。失败保留原控制器及轮次输出；需要恢复时，用同一计划、源码和轮次输出，指定新的控制器目录并加`--resume-round`。既有轮次检查拒绝变更后的模型、数据或配方，不覆盖失败控制器。

父进程显式启用已验证输入凭据，训练子进程沿用原有凭据入口；未变化的既有大文件按签名复用以前的完整字节核验，新产物仍重新绑定。模型训练控制台的URL和网络地址先脱敏再落盘。实际运行身份、输入输出证明及当前排队状态另见本次证据记录；此接口本身不证明GPU容量或棋力。
