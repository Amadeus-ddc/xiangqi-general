# 一手将死评分与训练变化的一致性

2026-11-06（UTC+8），训练标签审查发现：给定变化可以每步合法，却没有兑现其一手将死评分。新增可选检查要求主线及候选分支中的`mate +1/-1`评分与原始完整历史下的实际终局一致。检查用于后续数据收取，现役冻结源码、配置、已排队首轮开发蒸馏与既有评分记录均保持原样。

## 实际训练语料与对照

系统检查覆盖9823条实际初始讲解训练记录及首批318条搜索讲解，仅使用训练文件。初始集合125个一手将死评分段对应86个不同变化，均一致；新搜索集合27个评分段对应19个不同变化，其中11个变化、涉及11条记录未兑现其即时终局。主线与第一候选常重复，不能把评分段、变化、训练记录或独立棋局混为同一计数。这个结果没有证明其他讲解语义全部正确，也不否定这些根局面的最终胜负评分。

真实356份原教师回答的CPU对照中，旧模式完整重建318条接受与38条拒收，逐条匹配原产物。启用检查后保留307条、拒收49条；额外11条的ID与另一份系统核查完全一致，原38条拒收的原因与顺序保持。307条保留记录直接取原字节，内容和顺序未改。原9823条初始训练记录亦用新函数重查，零新增拒收。没有重新调用学生、专家神经网络、教师或皮卡鱼。

对照复用原已完成生产者的隔离证明：保留项是原接受记录的准确子集，原384／512保留文件摘要仍一致；没有重新构造全体保留位置集合，也没有据此伪造新的已完成训练集合清单。实际训练数据资格、全批去重、特征、词元和四卡预检仍由正式流水线执行。

## 检查内容

`mate +1`要求给定变化第一半步后，当前根行棋方实际获胜；`mate -1`要求根着法和对手应着两半步后，对手实际获胜。判断调用原生完整历史裁决，象棋困毙和其他已裁定规则胜也属于终局胜利，不要求末图必须将军。缺少所需变化前缀、原始历史不能抵达声明根、根已终局或变化未实现所称胜利，均拒收。

例如手工最小局面中，黑将`e7d7`后红`e5d5`只是将军，黑仍可`d7e7`，这段PV不能兑现`mate -1`；红改走`h6d6`才立即将死。根局面的输棋评分可以正确，给定讲解变化仍有问题。回归测试保留这一区别，并覆盖红黑胜方、真正将死、困毙、其他候选分支、缺失历史及不完整前缀。

检查不处理较长的杀步距离、普通厘兵分数、未列出的最优变化或正文全部战略声明。厘兵估计不能证明没有强制杀局；合法吃子之后可能有回吃。先前12例主代理抽查还发现了这些问题，但它不是盲评、人工验收或比例抽样，本次门槛也没有宣称解决它们。`all_strategic_prose_semantics_verified`仍为false。

## 使用与复验

独立收取入口使用`--require-immediate-mate-consistency`；搜索试批配置使用：

```json
{"require_immediate_mate_consistency": true}
```

协调器实际传递该选项，并把启用状态与固定profile记入新收取清单。默认省略该参数，保留旧集合配置及旧接受／拒收行为，避免重写历史实验。合并复验重新读取每个来源的配置与证明，检查实际保留记录，并按原模式从教师原答重建所有决定。配置、证明或profile互相冲突时拒绝合并。

新旧模式可以合并，但清单会记录启用的来源数量，以及是否全部来源都要求此检查；混合来源不能被描述成全体启用。完整战略语义仍须另行核查。相关161项CPU检查已通过；完整CPU及最终构建／发布记录见机器证据。
