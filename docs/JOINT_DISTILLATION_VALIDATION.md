# 蒸馏的完整讲解与旧课验证

原蒸馏入口沿用`validation_stages=["explanation"]`，即使四门旧课参与训练，也只用原讲解验证集的词元NLL选权重。旧实验及其选中0步的失败结论保留。

新配方显式选择`validation_profile="joint_explanation_and_course_replay_v1"`，并按顺序声明讲解及四门旧课。编译器只从已完成、无截断且未使用独立测试的分词预检取得各类实际验证数量，验证上限等于其总和；缺失旧课、改变原分割或自行填写不符数量均拒收。未选择该版本时，原配方、验证数量及完成字段保持原行为。

## 实际覆盖和完成证据

训练使用现有索引加载全部原始验证行，检查每个ID恰好出现一次，并记录各类数量与实际ID顺序的哈希。联合配置与数量属于轮次的精确续跑合同。轮次在训练前绑定完整验证选择计划，训练后从原始验证索引重建覆盖，并绑定原生训练保存的`validation_ids.json`，拒收缺项、重复、外来ID、未绑定的账本或与实际覆盖不符的指标。完成后重开只读取已绑定产物。原生训练循环及神经执行依赖保持原始字节，新检查集中在蒸馏编译及完成边界。

已对当前真实验证文件执行纯CPU读回：384条讲解、700条当前静态、600条当前动态、700条未来静态、600条未来动态，共2984条。原生索引与选择结果重开后，ID、输入／输出字节和修改时间保持一致。该读回没有加载模型、分词、重新裁定答案或访问独立测试文件。

## 新尝试的使用

[模板](../configs/search-distillation-sft-joint-validation-v1.json)是新的本地候选，使用四卡全参数FSDP2、全局批量32与四次有限遍历上限，并显式降低学习率。实际训练必须先绑定与分词预检完全相同的回放路径和数据；训练前仍需通过原生四卡容量及精确恢复预检。

```bash
python -m xqgeneral.distillation_training \
  --init runs/initial-sft/pipeline/sft/adapter.pt \
  --recipe configs/search-distillation-sft-joint-validation-v1.json \
  --token-preflight runs/completed-data-preflight/manifest.json \
  --output runs/new-joint-validation-round
```

请将路径换成该次已完成产物，并在新尝试目录运行。新的低学习率与共同验证是本地实验选择，不宣称原论文强制使用，也不能追溯改变旧实验的选模标准。

完整旧课训练覆盖与完整验证是两个独立合同。模板训练比例仍为讲解0.8、各旧课0.05；若要每次遍历使用全部旧课训练行，应按实际来源数量设置训练权重，并另行证明有限选择覆盖。编译器会把大于1的来源数量权重转换为概率，保持有限遍历的目标数量，使其可被SFT准备接口接受。

共同选模仍使用全部实际验证词元的NLL，长讲解的词元会贡献更多权重。这不是各科准确率的平均分，也不保证实战或讲解语义改善。新模型仍须单独通过原始走法、旧课问答、讲解和对弈验证；独立测试继续保留到最终模型和配置锁定后。

CPU检查覆盖显式版本、旧合同兼容、真实索引全覆盖、伪造账本拒收、受控正式轮次与完成重开。受控模型不证明实际多卡SGD或模型质量。
