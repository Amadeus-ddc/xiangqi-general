# 应将事实与机制监督

作者应将模板先点明受将的王、将军方，再按吃将军子、挡将和移王组织答案。项目新增显式配置，按中国象棋规则生成这类事实说明。它为后续同条件训练对照准备监督内容，尚未用于现役四课模型，不能解释或改善已报告的82%成绩。

## 配置及数据身份

| `--rationale-profile` | 逐着叙述给定未来 | 应将题说明将军方和解将机制 |
| --- | --- | --- |
| `paper_forward_moves_v1` | 是 | 沿用原正文 |
| `paper_parry_reasons_v1` | 否 | 当前与未来应将题 |
| `paper_forward_parry_v1` | 是 | 当前与未来应将题 |

逐着叙述的原有配置继续兼容，见[未来题说明](PAPER_FORWARD_RATIONALE.md)。应将说明在目标局面上生成，组合配置先叙述全部给定走子，再解释最终受将局面。只对相应范围内的题目生成新ID，`rationale_source_question_id`保留源题身份。题目、原始专家历史、特征键、给定未来和最终`答案：`标签保持一致。默认未启用时沿用原数据约定。

所有采样和颜色镜像先完成，再加入确定性的说明。生产清单和完整源读回绑定配置；删改配置声明会使读回失败。准备新数据时，使用既有完整源根、源清单和保留分割，新建输出与读回目录：

```bash
.venv/bin/python -m xqgeneral.paper_curriculum \
  --roots "$XQ_RATIONALE_ROOTS" --source-manifests "$XQ_RATIONALE_SOURCES" \
  --reference-data "$XQ_RATIONALE_PRIOR" \
  --rationale-profile paper_forward_parry_v1 --output "$XQ_RATIONALE_OUTPUT"
.venv/bin/python -m xqgeneral.paper_curriculum \
  --readback "$XQ_RATIONALE_OUTPUT" --output "$XQ_RATIONALE_READBACK"
```

## 象棋的解将机制

原生规则先确定受将将帅、将军棋子和全部合法解将着法，再用走前及走后的棋盘核对机制：吃掉将军棋子、移将帅、挡住车线、撤走炮架、添子阻隔炮线、塞住马腿。炮的两种阻挡变化分别核对炮线上的一枚屏障变为零枚或两枚，不能笼统地把所有非将帅着法称为挡将。同一着解除多个将军时保留每个将军方对应的机制。没有合法解将且正在被将军时明确说明将死。

例如，构造局面红帅e0、黑将e9、黑炮e5、黑马d2、红车e1中，黑炮与黑马同时将军。红车e1d1既撤走炮架，又塞住马腿；说明保留这两个机制。这个例子是规则测试局面，不冒充人类实战。

将帅照面的限制沿固定原生引擎的合法着法执行；新说明没有改变既有`in_check`标签语义，也不会把原生未标为将军的局面擅自改成应将题。非法给定变化、非受将局面或说明与金标不一致都会使准备失败。

## 已验证范围

真实来源开发输入覆盖训练100题、原验证100题、另400个棋局ID各一题的补充验证。600题共1744个合法解将响应，独立CPU Pikafish核对将军方、全部合法响应及走后局面；原始引擎输出另行读回。完整上游棋局的裁决不在本次参考范围内，FEN计数器也不进入监督文本。棋局ID不是独立物理对局的证明。

使用现役分词器和棋盘专用词元后，组合监督在这些样本内最长230 token，提示加监督最长359 token；样本未超过384生成预算或2048训练上限。完整题库仍需自己的索引、特征身份和词元预算预检。详见[软件与真实输入证据](../evidence/paper-parry-rationale-v1.json)。

现役冻结的89模块训练与已排队的训练／验证及特征诊断没有使用新格式。尚无新格式学生训练、正确率提升或教练能力结果。应先结合实际拟合与特征诊断决定训练对照，再记录新的数据、父模型和预算；当前可选文本功能不构成四课完成、讲解完成或模型交付。
