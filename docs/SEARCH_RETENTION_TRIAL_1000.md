# 1000步搜索讲解回放试验与32题原始对照

2026-11-14固定开发快照。新增搜索讲解与旧讲解／六类任务回放的训练实际完成1000次更新，但没有选出优于起点的模型。继续保留首轮辅助训练选中的12000步权重；正式成功搜索蒸馏轮次不增加。

[轻量证据](../evidence/search-retention-trial1000-raw32-v1.json)记录计数、原生验证值和私有收据摘要。原始模型回答、日志、权重与数据不随源码发布。

## 实际训练与选模

训练包含971条新搜索讲解、2048条原始讲解回放，以及六类任务各2048条回放，共15307条不同训练行；验证为完整原3749条。全局批量30，每个完整遍历511次更新，至少511步、最多2044步，每250步验证，连续四次未改善后早停。全解码器和桥接共624个可训练张量、4694274592个参数使用FP32，计算使用BF16，Adam动量在CPU。

| 权重位置 | 同一完整验证集的词元NLL（越低越好） |

| 起点 | 0.384295 |
| 250步 | 0.391019 |
| 500步 | 0.390459 |
| 750步 | 0.418234 |

实际消费3259117个监督词元、29977次训练行出现；出现次数含第二遍重复。最终原生脚本恢复起点后报告的0.384295属于所选起点，不能作为1000步权重改善的证据。完整1000步权重、优化器、随机状态和数据游标均保留。

内层训练正常完成；外层正式蒸馏拒收。逐项重建完成合同后，唯一未满足项是`selected_step > 0`，不能把它描述成未训练或硬件崩溃，也不能计作成功的新蒸馏轮。

## 原始讲解的同题对照

原12000步模型与未入选750步诊断权重，在相同32个原验证局面上各生成32份原始讲解。这里是29个声明棋局标识，含4条颜色镜像记录，不是32局独立实战。CPU FP32、相同输入／缓存特征、贪心生成和768词元预算；全部64份正常结束，没有截断或JSON解析失败。实际生成词元已独立重新解码，并用原生规则复核。

| 检查（每组32题） | 原模型 | 未入选750步 |
| --- | ---: | ---: |
| 首着合法 | 32 | 31 |
| 完整主变化可合法复演 | 20 | 19 |
| 完整讲解规则合同通过 | 4 | 3 |

完整合同逐题变化为：仅原模型通过4题、仅750步通过3题、两者均失败25题、两者均通过0题。该小型开发对照没有显示净规则收益，也不足以证明总体能力显著下降。它不建立CPU与GPU生成等价，不替代完整问答、讲解、对弈或最终独立验收。

规则通过只检查相应结构与棋盘事实；中文正文全部战术、战略和教学价值需要另外评审。现有失败主要包含主线与候选变化中的非法走法，不能以流畅中文或更长输出预算视为已经解决。

## 当前源码的完整教练流程实测

同一12000步开发模型已按139模块源码重新原生导出并搬到独立目录，624个FP32训练张量逐值保持一致。CPU原生`coach`实际从该包加载底座和专家，现场计算16层专家特征，没有传入训练特征缓存；生成一份417词元、正常EOS结束的完整讲解，然后接受一个合法用户走法、显示棋盘、悔棋并四次保存记录。文件访问跟踪中没有原模型、数据或训练检查点路径；原文件并未由操作系统隐藏，因此不作通用沙箱保证。

该回答仍有非法主变化和候选分支，原生界面确实提示核验失败，原文保持不变。这证明该次模型包加载和学习记录流程可执行，不证明模型已经能可靠教学。[流程证据](../evidence/portable139-full-coach-session-v1.json)单列软件执行与模型质量。
