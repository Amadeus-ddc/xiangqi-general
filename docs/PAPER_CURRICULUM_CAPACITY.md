# 正式课程批量的四卡容量验证

冻结解码器的课程配方已在四张 GPU 实际验证：**全局批量 256、每卡微批量 4、完整 2048 token**。预训练 Qwen3-4B 和固定 Px0 特征实际参与计算，671806496 个连接桥／棋盘参数以 FP32 更新；连续两步与一步后恢复再走一步的全部参数、优化器、随机状态、数据位置、选模状态和日志一致。见[轻量证据](../evidence/paper-curriculum-capacity-v1.json)。

| 指标 | 实际结果 |
| --- | --- |
| rank 0 分配显存峰值 | 连续 79.82 GiB；恢复 79.87 GiB |
| 四卡设备使用量最高值 | 86505 MiB，包含分配器保留与设备开销 |
| 全宽桥接 | 16 层、宽度 2560、16 个注意力头 |
| 完整训练状态 | 226 个张量；671806496 个有限 FP32 参数 |
| 恢复差异 | 零个不同张量；最大参数误差 0 |
| 正式 GPU 执行源码 | 同一份冻结的 88 个模块 |

输入是先前完成原生复核的 21 道训练题和 14 道验证题，共五个完整历史。控制在原问题前添加明确标记的长度填充，构造 512 次训练呈现；全部训练／验证输入及完整答案恰好 2048 token，没有截断。原棋局、完整历史、查询和答案保持一致。这些重复呈现和填充仅检查容量，没有加入生产语料，也不证明实际问答正确率、棋力或教学质量。

独立入口重新哈希全部 43 份约 24.21 GB 的绑定，重新计算 35 道原生答案，逐条重建 526 个填充输入并通过正式索引读取，对照完整训练／选模状态及 837 次四卡显存记录。特征存储为 FP16，正式 `gather_features` 输出 BF16；全部转换值和有限性核对通过。首次复核误把运行时类型当作存储类型，其失败记录保留；修订仅涉及复核入口，GPU 实验和正式源码没有更改。

这次验证使用原配方的 AdamW 设置：`optimizer_foreach: null`、`ddp_gradient_as_bucket_view: false`，解码器为 BF16 且冻结。最长窗口下更新成功，无需为课程更改这些设置。初始讲解的全解码器 SFT 使用另外的显存设置和预检，仍依次等待四门课程全部完成，见[后续训练流程](PAPER_POST_CURRICULUM.md)。

本服务器控制在 `runs/paper-curriculum-capacity-v1/worktree/runs/full-window-batch256-v1/`，完整独立复核在同级 `full-window-batch256-readback-v2/`。两者均退出成功；入口、配置、源码快照和哈希保存在各目录，模型、填充数据及日志不随源码发布。全套 1452 项检查通过，186 份源码／测试／测试配置不变。

正式 `xqgeneral-paper-curriculum-preparation-v7` 继续生成新课程语料；其输入、配方和运行入口保持已冻结合同。完整金标复核、专家缓存、索引和基础预检通过后才启动正式四课；当前正式更新仍为零。
